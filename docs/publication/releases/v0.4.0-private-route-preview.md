# v0.4.0 — Private complete-route preview

NETWORK AI can now admit and settle a complete route with one root agent and separately signed stage agents. A real official Qwen3-32B Q4_K_M model executed through two guarded CPU workers on one computer. This release advances the local implementation; independent-provider operation remains under development.

## Behavior added

- A root owner proposes immutable participant and payout terms; every provider accepts their exact hash. The browser supports proposal, consent, withdrawal and administrative qualification.
- Admission reserves every required physical domain atomically. Several stages on one computer share its slot rather than creating extra physical capacity.
- Stages prepare and consume single-use claims before the root can generate. Their bounded local RPC guards observe completed compute commands.
- Settlement requires valid completed root and stage receipts. One provider pool is divided according to frozen shares, conserving all integer micro-units. Participant amounts are visible in session details without truncating meaningful digits.
- Missing evidence, expired/fenced attempts, cancellation and stage failure prevent a successful charge. Stage receipts have a durable retry outbox.
- The managed 32B installer, launcher and shutdown path handle the three-agent CPU group. The existing CPU profile is retained without loading two 32B copies. Backup verification now covers route tables and participant payout projections.

## Validation

Local automated checks passed: 34 PostgreSQL integration tests, 7 artifact/RPC socket tests, 9 Rust tests, 21 preserved Python F0 tests and 6 browser journeys. Build, type checking, formatting, Clippy and repository checks passed. An isolated PostgreSQL restore preserved the balanced journal, route history and runtime restrictions.

The real 32B route campaign completed three requests. Each worker reported six completed graph commands per request; two simultaneous calls did not overlap the one shared slot. Killing one stage during a separate generation produced `FAILED / REFUNDED` with zero charge while the client remained connected. After installation and a complete stop/start cycle, a real browser-proxy request also completed and settled with both stage receipts.

The pinned engine needed one computation per worker during initialization. An explicit nonbillable startup allowance is bounded and closes when the model first becomes ready. It creates no credits. The default stage-agent allowance is zero.

## Read before using

The measured topology was **one physical host, one operator account, CPU workers and a single coordinator**. Separate signatures are not independent work verification. Raw llama.cpp RPC stays on loopback and remains upstream prototype code. This release does not qualify WAN/RDMA exposure, heterogeneous GPUs, adversarial providers, economic viability, distributed consensus or cash payments. Rates and the measured 10/45/45 provider split are experimental.
